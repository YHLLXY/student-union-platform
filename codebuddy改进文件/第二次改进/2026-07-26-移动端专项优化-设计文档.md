# 移动端专项优化 — 设计文档

> **状态：** 草案（待讨论） | **日期：** 2026-07-26 | **范围：** 仅移动端 | **前置：** v3.4 UI 优化已完成

## 一、背景与目标

### 1.1 现状

v3.4 完成了「精致极简风格 + CSS 变量体系」，但移动端只做到了「不破」，没做到「好用」。基于已交付的 16 个文件做系统审查，发现 **6 个系统性问题** + 多个模块级问题。

通俗说：现在手机上能用，但体验粗糙——搜索入口消失、表格挤成一条、看板拖不动、刘海挡内容、点下去没反馈。

### 1.2 核心约束（用户明确）

| 约束 | 说明 |
|------|------|
| 🔒 仅改移动端 | 所有改动在移动断点内生效，**桌面端（≥1024px）行为零变化** |
| 🔒 移动端不允许拖拽 | Kanban、文件上传等模块在手机上用「点击」替代「拖拽」 |
| 🔒 不引入新 UI 框架 | 继续用 CSS Modules + Ant Design 6 + React 19 |
| ✅ 复用 v3.4 基建 | CSS 变量体系、动画体系直接用，不重造 |

### 1.3 优化目标

1. **断点体系**：从 1 档（768px）补全到 3 档（480 / 768 / 1024）
2. **触摸交互可用**：按压反馈、≥44px 触摸目标、无 hover 依赖
3. **安全区适配**：刘海 / 底部指示条不遮挡内容
4. **重灾区解决**：Kanban 点击模式、表格卡片化
5. **功能性修复**：手机端恢复全局搜索入口

## 二、设计决策

### 2.1 断点体系

| 断点 | 含义 | 典型设备 |
|------|------|------|
| `≤480px` | 小屏手机 | iPhone SE / Android 360 |
| `481–768px` | 大屏手机 / 小平板竖屏 | iPhone Plus / iPad mini 竖 |
| `769–1024px` | 平板 | iPad 横 / Android 平板 |
| `≥1024px` | 桌面 | **不动** |

CSS 写法沿用 `max-width` 从大到小覆盖：
```css
@media (max-width: 1024px) { /* 平板 */ }
@media (max-width: 768px)  { /* 大屏手机 */ }
@media (max-width: 480px)  { /* 小屏手机 */ }
```

### 2.2 触摸交互规范

- 所有可点元素加 `:active` 按压反馈（`transform: scale(0.98)` 或 `opacity: 0.85`）
- 触摸目标最小 **44×44px**（AntD Input/Button 在移动端覆盖到 44px 高）
- 全局 `-webkit-tap-highlight-color: transparent` 去掉灰色闪屏
- `touch-action` 按需设置，避免横向滑动误触垂直滚动
- **禁用**：hover-only 交互、原生 HTML5 拖拽

### 2.3 Kanban 移动端方案（关键决策）

> 用户明确：移动端不允许拖拽。

**桌面端（≥768px）**：保留现有拖拽，零改动。

**移动端（<768px）**：
- 看板横向滚动 + `scroll-snap`，一次显示一列（`85vw`），露出下一列边缘提示可滑
- 卡片**不可拖**，点击打开详情
- 详情内用 `Segmented` 或 `Select` 切换状态（= 移动到其他列），调用与拖拽**相同的后端接口**
- 由 `Grid.useBreakpoint()` 在 `KanbanBoard.tsx` 内切换交互模式，保证桌面端逻辑完全不变

通俗说：手机上看板像翻页一样左右滑看不同状态列，点开一张卡片后在里面选「移到进行中」「移到已完成」，效果跟电脑上拖过去一样。

### 2.4 表格移动端方案（待讨论，默认采用 B）

AntD Table 在 375px 屏多列表格会溢出或挤成一条。三个候选：

| 方案 | 做法 | 体验 | 工作量 | 风险 |
|------|------|:--:|:--:|:--:|
| A 横向滚动 | `scroll={{x:true}}` | 差 | 极小 | 低 |
| **B 断点切换（推荐）** | `useBreakpoint()` 桌面 `<Table>` / 移动 `<List>` 卡片 | 好 | 中 | 中 |
| C 纯 CSS 堆叠 | `data-label` + CSS 把单元格堆成卡片 | 中 | 大（每表手写） | 中 |

**默认采用 B**：在受影响页面用 `Grid.useBreakpoint()` 判断，移动端渲染卡片列表，桌面端渲染原 Table。卡片样式抽成共享组件 `<MobileCardList>` 复用。

> ⚠️ 此项待用户确认。若选 C，实施计划 Phase D 步骤需调整。

### 2.5 安全区适配

`viewport-fit=cover` 已在 `index.html`，CSS 补 `env(safe-area-inset-*)`：
- Header 顶部内边距（防刘海 / 状态栏遮挡）
- Content 底部内边距（防 home 指示条遮挡）
- PWA 更新 toast 底部位置

### 2.6 不做（本期范围外）

- ❌ 暗色模式（留后续）
- ❌ 复杂手势（滑动删除、长按菜单等，除非必要）
- ❌ 引入手势库（hammer.js 等）
- ❌ 改动桌面端任何视觉 / 交互

## 三、全局基础设施改动

### 3.1 `variables.css` 增补移动端变量

```css
/* ---- 移动端专用 ---- */
--touch-target: 44px;
--safe-area-top: env(safe-area-inset-top, 0px);
--safe-area-bottom: env(safe-area-inset-bottom, 0px);
--mobile-content-padding: 16px;
--mobile-card-gap: 12px;
```

### 3.2 `index.html` viewport 修正

现状：`maximum-scale=1.0, user-scalable=no` —— 禁止缩放，违反 WCAG 1.4.4 无障碍标准，弱视用户无法放大。
改为：保留 `viewport-fit=cover`，去掉缩放限制。

### 3.3 `AppLayout` 改动

| 改动 | 原因 |
|------|------|
| Header 加 `padding-top: var(--safe-area-top)` | 防刘海遮挡 |
| Content 加底部安全区内边距 | 防底部指示条遮挡 |
| 手机端恢复全局搜索入口（Header 搜索图标 → Drawer） | 现 `AppLayout.tsx:170` 在 `<md` 时直接不渲染搜索，手机用户无法搜索 |
| `<480px` 隐藏用户名只留头像 | Header 空间不够 |
| 反馈 / 指南按钮移入用户下拉菜单 | 现在手机端被隐藏，功能丢失 |

### 3.4 全局触摸工具样式

新增到 `animations.css` 或 `variables.css` 末尾（全局非 module 文件）：
```css
/* 去除移动端点击灰色闪屏 */
* { -webkit-tap-highlight-color: transparent; }

/* 通用按压反馈工具类（CSS Module 内按需引用） */
.tap-feedback:active { transform: scale(0.98); transition: transform 0.1s; }
```

## 七、风险与缓解

| 风险 | 概率 | 缓解 |
|------|:--:|------|
| Kanban 改动碰业务逻辑 | 中 | 桌面端走原拖拽路径不变，移动端复用同一状态更新接口；改前 grep 确认调用方 |
| 表格卡片化工作量超预期 | 中 | 优先做 Dashboard/Admin/Tasks 三个高频；其余延后 |
| AntD Table `components` 改造影响排序 / 分页 | 中 | 方案 B 用断点切换而非改 Table 内部，桌面端 Table 零改动 |
| `100dvh` 旧浏览器不支持 | 低 | 保留 `100vh` 在前作兜底 |
| 安全区变量在非刘海机为 0 | 低 | `env(..., 0px)` 兜底 |
