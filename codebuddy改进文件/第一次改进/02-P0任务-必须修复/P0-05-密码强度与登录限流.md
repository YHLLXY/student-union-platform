## 🎯 任务背景

当前问题：
1. **无密码强度校验**：`signUp` 直接把密码传给 Supabase Auth，用户可能用 `123456`。
2. **无登录失败限流**：Supabase 免费档默认无限流，可被枚举学号 + 字典撞库。
3. **学号可枚举**：学号有规律（年份+院系+序号），是弱身份标识。

## ✅ 完成目标

1. 注册时前端校验密码强度（≥8 位 + 字母数字混合）。
2. 登录失败 5 次后锁定 15 分钟（按学号 + IP）。
3. 锁定期间登录直接拒绝，不查询 Auth。
4. 限流用 Supabase RPC 实现（前端调用 `check_login_limit` 在 `signIn` 前检查）。

### 2. SQL 迁移内容

```sql
-- ============================================================
-- 第十六部分：登录限流（P0-05）
-- ============================================================

-- 1. 登录尝试记录表
CREATE TABLE IF NOT EXISTS auth_attempts (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  identifier TEXT NOT NULL,          -- 学号（学生会场景数据不敏感，直接存）
  success BOOLEAN NOT NULL,
  attempted_at TIMESTAMPTZ DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_auth_attempts_identifier_time 
  ON auth_attempts(identifier, attempted_at DESC);

-- 2. 检查是否被锁定（最近 15 分钟失败次数 >= 5）
CREATE OR REPLACE FUNCTION check_login_limit(p_identifier TEXT)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public
AS $$
DECLARE
  fail_count INTEGER;
  latest_fail TIMESTAMPTZ;
BEGIN
  SELECT count(*), max(attempted_at)
  INTO fail_count, latest_fail
  FROM auth_attempts
  WHERE identifier = p_identifier
    AND success = false
    AND attempted_at > now() - INTERVAL '15 minutes';

  IF fail_count >= 5 THEN
    RETURN jsonb_build_object(
      'locked', true,
      'message', '登录失败次数过多，请 15 分钟后再试',
      'retry_after', latest_fail + INTERVAL '15 minutes'
    );
  END IF;

  RETURN jsonb_build_object('locked', false, 'message', '');
END;
$$;

-- 3. 记录登录尝试
CREATE OR REPLACE FUNCTION record_login_attempt(p_identifier TEXT, p_success BOOLEAN)
RETURNS VOID
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public
AS $$
BEGIN
  INSERT INTO auth_attempts (identifier, success) VALUES (p_identifier, p_success);
  
  -- 清理 7 天前的旧记录（避免表无限增长）
  DELETE FROM auth_attempts WHERE attempted_at < now() - INTERVAL '7 days';
END;
$$;

-- 4. RLS：用户只能调用 RPC，不能直接查 auth_attempts
ALTER TABLE auth_attempts ENABLE ROW LEVEL SECURITY;
-- 不创建任何 policy = 所有直接查询被拒，只能通过 SECURITY DEFINER 的 RPC 访问
```

### 3. authService.ts 改动点

#### 3.1 新增 validatePasswordStrength

```typescript
/** 密码强度校验：≥8位 + 至少含字母和数字 */
export function validatePasswordStrength(password: string): { valid: boolean; message: string } {
  if (password.length < 8) {
    return { valid: false, message: '密码至少 8 位' };
  }
  if (!/[a-zA-Z]/.test(password)) {
    return { valid: false, message: '密码必须包含字母' };
  }
  if (!/[0-9]/.test(password)) {
    return { valid: false, message: '密码必须包含数字' };
  }
  return { valid: true, message: '' };
}
```

#### 3.3 signIn 改造（限流）

```typescript
export async function signIn(
  studentId: string,
  password: string,
): Promise<{ user: UserProfile | null; error: string | null }> {
  // 1. 检查是否被锁定
  const { data: limitData, error: limitError } = await supabase.rpc('check_login_limit', {
    p_identifier: studentId,
  });

  if (limitError) {
    log.error('check_login_limit RPC 失败', limitError);
    // RPC 失败不阻塞登录（降级策略）
  } else if (limitData) {
    const limit = limitData as { locked: boolean; message: string };
    if (limit.locked) {
      return { user: null, error: limit.message };
    }
  }

  // 2. 尝试登录
  const email = `${studentId}@stuunion.org`;
  const { data: authData, error: authError } = await supabase.auth.signInWithPassword({
    email,
    password,
  });

  // 3. 记录登录尝试（fire-and-forget，不阻塞）
  const success = !authError && !!authData.user;
  supabase.rpc('record_login_attempt', {
    p_identifier: studentId,
    p_success: success,
  }).catch(() => {});

  if (authError || !authData.user) {
    return { user: null, error: authError?.message ?? '登录失败' };
  }

  // 4. 获取用户完整信息
  const { data: userData, error: userError } = await supabase
    .from('users')
    .select('*')
    .eq('auth_id', authData.user.id)
    .single();

  if (userError || !userData) {
    return { user: null, error: '用户信息不存在' };
  }

  return { user: userData as UserProfile, error: null };
}
```

## ⚠️ 风险与回滚

**风险 1：** RPC 失败导致所有登录被阻塞。

**应对：** `signIn` 里 RPC 失败时降级（跳过限流继续登录），见 Prompt 里的 `if (limitError) { log.error(...); }`。

**风险 2：** 自己被锁定了无法登录测试。

**应对：**
```sql
DELETE FROM auth_attempts WHERE identifier = '你的学号';
```

**风险 3：** 密码强度校验太严，老用户改密码时被拦。

**应对：** 本任务只在 `signUp`（注册）和 `changePassword`（改密）时校验，不影响 `signIn`。如果老用户密码不符合新策略，登录仍可正常，只是改密码时需要符合新规则。
