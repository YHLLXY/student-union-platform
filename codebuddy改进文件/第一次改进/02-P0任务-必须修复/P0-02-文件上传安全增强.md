## 🎯 任务背景

当前 `FileUpload.tsx` **已有基础校验**（白名单 MIME + 扩展名 + 10MB 限制），做得不错。但存在以下缺口：

1. **SVG XSS 风险**：`image/svg+xml` 在白名单里，SVG 可内嵌 `<script>`，若通过 `<img>` 或 `<iframe>` 内联展示会执行 JS。
2. **MIME 可伪造**：前端 `file.type` 来自浏览器嗅探，可被改。应结合文件头（magic number）二次校验关键类型。
3. **Storage DELETE 策略过宽**：当前 `storage.objects` 的 DELETE 策略是 `auth.role() = 'authenticated'`，**任何登录用户都能删任何人的附件**。
4. **文件名路径注入**：当前 `safeName` 正则 `[^a-zA-Z0-9._一-鿿-]` 基本够用，但应额外防 `..` 路径穿越。

## ✅ 完成目标

1. 从白名单移除 `image/svg+xml`（学生会场景不需要 SVG 上传）。
2. 关键类型（图片）加 magic number 校验。
3. 文件名额外过滤 `..` 序列。
4. 修正 Storage DELETE 策略为"仅 owner 可删"。
5. 上传时记录 `owner` 元数据（metadata），用于 DELETE 策略判断。

#### 2.3 新增 magic number 校验函数

```typescript
// 图片类型的 magic number 映射
const IMAGE_SIGNATURES: Record<string, number[]> = {
  'image/jpeg': [0xFF, 0xD8, 0xFF],
  'image/png': [0x89, 0x50, 0x4E, 0x47],
  'image/gif': [0x47, 0x49, 0x46, 0x38],
  'image/webp': [0x52, 0x49, 0x46, 0x46], // RIFF
};

/** 校验图片文件头（magic number），防伪造 MIME */
async function validateImageSignature(file: File): Promise<boolean> {
  if (!file.type.startsWith('image/')) return true; // 非图片不校验
  const expected = IMAGE_SIGNATURES[file.type];
  if (!expected) return true; // 未知图片类型放行（如 image/heic）
  
  const buffer = await file.slice(0, expected.length).arrayBuffer();
  const bytes = new Uint8Array(buffer);
  return expected.every((byte, i) => bytes[i] === byte);
}
```

**风险 1：** 旧附件没有 `metadata.owner`，DELETE 策略改变后用户无法删除旧附件。

**应对：** 给旧附件补 owner。执行：
```sql

```

**风险 2：** magic number 校验误伤合法图片（如 HEIC）。

**应对：** `validateImageSignature` 对未知类型（不在 `IMAGE_SIGNATURES` 里的）直接返回 `true` 放行。
