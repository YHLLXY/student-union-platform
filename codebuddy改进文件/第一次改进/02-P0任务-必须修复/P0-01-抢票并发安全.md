## 🎯 任务背景

当前 `grabTicket` 实现存在 **TOCTOU（Time-of-Check to Time-of-Use）竞态**：

```
1. 查询 totalGrabbed = 99（total_count=100）
2. 查询 myCount = 0（per_user_limit=1）
3. 判断 99 < 100 → 通过
4. INSERT ticket_records
```

如果两个用户在步骤 3 和 4 之间并发，都会通过检查，导致 `ticket_records` 实际数量 = 101，**超卖 1 张**。

虽然 `ticket_records` 有 `UNIQUE(ticket_id, user_id)` 防重复抢，但**不防超卖**。

## ✅ 完成目标

- 抢票改为单个 RPC 调用，在数据库层原子完成"检查余票 + 检查用户限额 + 插入记录"。
- 任何并发场景下都不会超卖。
- 保留现有错误消息语义（未到开抢时间 / 已抢过 / 已抢完 / 限抢 N 张）。

RETURNS BOOLEAN
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
BEGIN
  UPDATE auth.users
  SET encrypted_password = crypt(new_password, gen_salt('bf'))

### 2. RPC 函数设计要求

函数签名：`grab_ticket(p_ticket_id UUID, p_user_id UUID, p_student_id TEXT, p_name TEXT) RETURNS JSONB`

返回格式（用 `jsonb_build_object`）：
- 成功：`{"success": true, "message": "抢票成功！"}`
- 失败：`{"success": false, "message": "具体原因"}`

函数体内逻辑（全部在一个事务里）：
1. `SELECT * FROM tickets WHERE id = p_ticket_id FOR UPDATE;` —— 行级锁防并发
2. 检查 `open_time <= now()`，否则返回"尚未到开抢时间"
3. `SELECT count(*) FROM ticket_records WHERE ticket_id = p_ticket_id AND user_id = p_user_id;`
4. 检查 `my_count >= per_user_limit`，返回"每人限抢 N 张"
5. `SELECT count(*) FROM ticket_records WHERE ticket_id = p_ticket_id;`
6. 检查 `total >= total_count`，返回"票已被抢完"
7. `INSERT INTO ticket_records ...`，捕获唯一约束冲突返回"你已抢过该票"
8. 异常处理：`EXCEPTION WHEN OTHERS THEN` 返回"抢票失败，请重试"

用 `SECURITY DEFINER`，开头 `SET search_path = public;`。

### 3. 前端 grabTicket 改写要求

```typescript
export async function grabTicket(
  ticketId: string,
  userId: string,
  studentId: string,
  name: string,
): Promise<{ success: boolean; message: string }> {
  const { data, error } = await supabase.rpc('grab_ticket', {
    p_ticket_id: ticketId,
    p_user_id: userId,
    p_student_id: studentId,
    p_name: name,
  });

  if (error) {
    log.error('grabTicket RPC 调用失败', error);
    return { success: false, message: '抢票失败，请重试' };
  }

  // data 是 { success, message } 的 JSONB
  return (data as { success: boolean; message: string }) ?? { success: false, message: '抢票失败' };
}
```
