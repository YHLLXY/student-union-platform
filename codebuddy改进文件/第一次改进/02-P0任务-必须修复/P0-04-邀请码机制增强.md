## 🎯 任务背景

当前 `invite_codes` 表结构极简：

```sql
CREATE TABLE invite_codes (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  code TEXT UNIQUE NOT NULL,
  department TEXT NOT NULL,
  role TEXT NOT NULL DEFAULT 'volunteer',
  is_used BOOLEAN DEFAULT false,
  used_by UUID REFERENCES users(id),
  created_at TIMESTAMPTZ DEFAULT now()
);
```

**问题：**
1. **无过期机制**：邀请码永久有效，学长毕业后码泄漏仍可注册。
2. **无撤销能力**：`is_used` 只能从 false→true，无法主动作废一个未用的码。
3. **无使用次数上限**：虽然 `is_used` 配合"一次性"语义，但无法支持"招新批量码"（如新生招新期间一个码 50 人用）。
4. **无创建者记录**：不知道谁发了这个码，无法审计。
5. **`checkInviteCode` 只查 `is_used=false`**，改表后要同步更新校验逻辑。

## ✅ 完成目标

1. `invite_codes` 表新增 `max_uses`、`used_count`、`expires_at`、`created_by`、`revoked_at` 字段。
2. `checkInviteCode` 校验逻辑更新：未撤销 + 未过期 + 用量未满。
3. `signUp` 注册成功后 `used_count` +1（而非简单置 `is_used=true`）。
4. 管理员可在后台撤销邀请码（`revoked_at` 字段）。
5. 兼容现有数据：旧码默认 `max_uses=1, used_count=0`，`is_used=true` 的旧码 `used_count=1`。

### 3. authService.ts 改动点

#### 3.1 checkInviteCode 更新校验逻辑

```typescript
/** 检查邀请码是否有效：未撤销 + 未过期 + 用量未满 */
export async function checkInviteCode(code: string) {
  const { data, error } = await supabase
    .from('invite_codes')
    .select('*')
    .eq('code', code)
    .is('revoked_at', null)           // 未撤销
    .or(`expires_at.is.null,expires_at.gt.${new Date().toISOString()}`)  // 未过期
    .lt('used_count', 'max_uses')     // 用量未满（用字符串避免类型问题）
    .maybeSingle();

  if (error || !data) return null;
  return data;
}
```

**注意：** `.lt('used_count', 'max_uses')` 这种列对列比较在 postgrest-js 里不支持。需要改用 RPC 或过滤器。实际实现请用：
- 方案 A：查询后客户端判断 `data.used_count < data.max_uses`
- 方案 B：建一个 RPC `check_invite_code(p_code TEXT) RETURNS TABLE(...)`

**请采用方案 A**（更简单，符合项目"不引入 RPC 除非必要"的风格）：

```typescript
export async function checkInviteCode(code: string) {
  const { data, error } = await supabase
    .from('invite_codes')
    .select('*')
    .eq('code', code)
    .is('revoked_at', null)
    .maybeSingle();

  if (error || !data) return null;

  // 客户端二次校验
  if (data.expires_at && new Date(data.expires_at) < new Date()) return null;
  if (data.used_count >= data.max_uses) return null;

  return data;
}
```

#### 3.2 signUp / signUpTeacher 标记邀请码已用

把原来的：
```typescript
await supabase
  .from('invite_codes')
  .update({ is_used: true, used_by: userData.id })
  .eq('code', inviteCode);
```

改为：
```typescript
await supabase
  .from('invite_codes')
  .update({
    used_count: (inviteData?.used_count ?? 0) + 1,
    used_by: userData.id,
    is_used: ((inviteData?.used_count ?? 0) + 1) >= (inviteData?.max_uses ?? 1),
  })
  .eq('code', inviteCode);
```

**注意：** 这里 `inviteData` 是 `checkInviteCode` 返回的数据，需要把 `checkInviteCode` 的返回值传给 `signUp`，或在 `signUp` 内部重新查询。请选择"在 signUp 内部重新查询邀请码"（保持函数签名不变）。

#### 3.3 新增 revokeInviteCode 函数（管理员用）

```typescript
/** 撤销邀请码（管理员） */
export async function revokeInviteCode(codeId: string): Promise<boolean> {
  const { error } = await supabase
    .from('invite_codes')
    .update({ revoked_at: new Date().toISOString() })
    .eq('id', codeId);

  if (error) { log.error('revokeInviteCode 失败', error); return false; }
  return true;
}
```
