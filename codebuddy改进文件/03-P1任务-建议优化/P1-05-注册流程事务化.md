## 🎯 任务背景

**问题：** `signUp` 顺序执行三步，中途断网会留下不一致状态：
1. 创建 Auth 用户 ✅
2. 写 users 表 ❌（断网）→ Auth 用户存在但没有 profile
3. 标记邀请码已用 ❌（未执行）→ 邀请码仍可用

下次注册显示"已注册"但登录后无数据。

**当前实现：**
```typescript
export async function signUp(...) {
  // 1. supabase.auth.signUp()
  // 2. supabase.from('users').insert(...)
  // 3. supabase.from('invite_codes').update(...)
}
```

## ✅ 完成目标

1. 用 Supabase RPC 把"校验邀请码 + 创建 users 记录 + 标记邀请码已用"包成一个事务。
2. Auth 用户创建仍在前端（Supabase Auth API 限制），但后续步骤事务化。
3. 断网时 Auth 用户虽已创建，但可通过"孤儿清理"或"重试注册"恢复。

### 2. SQL RPC 定义

```sql
-- ============================================================
-- 第十八部分：注册流程事务化（P1-05）
-- ============================================================

CREATE OR REPLACE FUNCTION register_student(
  p_auth_id UUID,
  p_name TEXT,
  p_student_id TEXT,
  p_invite_code TEXT
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public
AS $$
DECLARE
  v_invite RECORD;
  v_user_id UUID;
BEGIN
  -- 1. 查询邀请码（行级锁，防并发）
  SELECT * INTO v_invite
  FROM invite_codes
  WHERE code = p_invite_code
    AND revoked_at IS NULL
  FOR UPDATE;

  -- 2. 校验邀请码
  IF NOT FOUND THEN
    RETURN jsonb_build_object('success', false, 'error', '邀请码无效或已被撤销');
  END IF;

  IF v_invite.expires_at IS NOT NULL AND v_invite.expires_at < now() THEN
    RETURN jsonb_build_object('success', false, 'error', '邀请码已过期');
  END IF;

  IF v_invite.used_count >= v_invite.max_uses THEN
    RETURN jsonb_build_object('success', false, 'error', '邀请码已被使用完毕');
  END IF;

  -- 3. 检查学号是否已注册
  IF EXISTS (SELECT 1 FROM users WHERE student_id = p_student_id) THEN
    RETURN jsonb_build_object('success', false, 'error', '该学号已注册');
  END IF;

  -- 4. 插入 users 记录
  INSERT INTO users (auth_id, name, student_id, department, role)
  VALUES (p_auth_id, p_name, p_student_id, v_invite.department, v_invite.role)
  RETURNING id INTO v_user_id;

  -- 5. 标记邀请码已用（used_count + 1，is_used 同步）
  UPDATE invite_codes
  SET 
    used_count = used_count + 1,
    used_by = v_user_id,
    is_used = (used_count + 1) >= max_uses
  WHERE code = p_invite_code;

  -- 6. 返回用户信息
  RETURN jsonb_build_object(
    'success', true,
    'user', jsonb_build_object(
      'id', v_user_id,
      'auth_id', p_auth_id,
      'name', p_name,
      'student_id', p_student_id,
      'department', v_invite.department,
      'role', v_invite.role
    )
  );

EXCEPTION WHEN OTHERS THEN
  RETURN jsonb_build_object('success', false, 'error', '注册失败：' || SQLERRM);
END;
$$;
```

### 3. authService.ts signUp 改造

```typescript
export async function signUp(
  name: string,
  studentId: string,
  inviteCode: string,
  password: string,
  department: string,  // 保留参数（向后兼容），但实际从邀请码取
  role: string,        // 同上
): Promise<{ user: UserProfile | null; error: string | null }> {
  // 1. 密码强度校验（P0-05）
  const pwdCheck = validatePasswordStrength(password);
  if (!pwdCheck.valid) {
    return { user: null, error: pwdCheck.message };
  }

  // 2. 创建 Auth 用户
  const email = `${studentId}@stuunion.org`;
  const { data: authData, error: authError } = await supabase.auth.signUp({
    email,
    password,
  });

  if (authError || !authData.user) {
    return { user: null, error: authError?.message ?? '注册失败，请重试' };
  }

  // 3. 调用 RPC 完成注册（事务化）
  const { data: rpcData, error: rpcError } = await supabase.rpc('register_student', {
    p_auth_id: authData.user.id,
    p_name: name,
    p_student_id: studentId,
    p_invite_code: inviteCode,
  });

  if (rpcError) {
    log.error('register_student RPC 失败', rpcError);
    // RPC 失败但 Auth 用户已创建 → 提示用户联系管理员清理
    return { user: null, error: '注册流程异常，请联系管理员（Auth 用户已创建）' };
  }

  const result = rpcData as { success: boolean; error: string; user: UserProfile };

  if (!result.success) {
    // RPC 内部校验失败（邀请码无效等）→ Auth 用户已创建但是孤儿
    log.error('register_student 校验失败', result.error);
    return { user: null, error: result.error + '（Auth 用户已创建，请勿重复注册）' };
  }

  return { user: result.user, error: null };
}
```

**注意：** `department` 和 `role` 参数保留但不再使用（从邀请码取）。这是为了向后兼容调用方。

## ⚠️ 风险与回滚

**风险 1：** RPC 里 EXCEPTION 吞掉了具体错误。

**应对：** RPC 返回 `SQLERRM` 帮助调试。生产环境可以把错误日志写入单独表。

**风险 2：** Auth 用户已创建但 RPC 失败，用户无法重新注册。

**应对：**
- 短期：提示用户"联系管理员"，管理员在 Supabase Dashboard 手动删除孤儿 Auth 用户。
- 长期：加 GitHub Action 定时清理孤儿（记到 ISSUES.md，不在本任务做）。

**回滚：**
```bash
git checkout HEAD -- src/modules/auth/authService.ts
# RPC 保留无害（不被调用即可）
```
