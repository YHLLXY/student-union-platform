# 暗色模式与仪表盘 UI 参考

> v4.0 迭代调研沉淀 · 2026-09-03
> antd 6.4.5 本地验证（`node_modules/antd/es/theme/index.d.ts`）+ 2025-2026 优秀产品 UI 模式归纳。

## 一、antd 6 暗色模式正确姿势

### 双算法 + 令牌覆盖

```ts
import { theme as antdTheme } from 'antd';
// 亮色：theme.defaultAlgorithm（默认，可省略）
// 暗色：theme.darkAlgorithm
const darkTheme: ThemeConfig = {
  algorithm: antdTheme.darkAlgorithm,
  token: { colorPrimary: '#2f6db3', /* 深底上把品牌色提亮一档 */ ... },
};
```

验证结论：antd 6.4.5 的 `es/theme/index.d.ts` 仍导出 `defaultAlgorithm / darkAlgorithm / compactAlgorithm`，v5 时代的算法模式在 v6 完全延续；`useToken()` 返回值额外带 `cssVar`（v6 CSS 变量模式深化，但算法切换仍是主题切换的正解）。

### 关键经验

1. **暗色下品牌主色必须提亮**：#1a3a5c 深蓝在深底上按钮对比度不足，暗色 token 单独给 #2f6db3。
2. **antd token 与 CSS 变量双轨同步**：antd 组件走 `darkAlgorithm`，自绘 CSS 走 `variables.css [data-theme='dark']` 覆盖块，两处的语义色值保持一致（本项目 base 色 #101418 / 卡片 #171c22）。
3. **首帧防闪**：`<head>` 内联脚本在 CSS 绘制前读 localStorage 写 `document.documentElement.dataset.theme`，否则暗色用户每次进站白闪一次。
4. **三态切换**：light / dark / system（跟随 `prefers-color-scheme`，并监听 change 事件实时响应）。持久化 localStorage。antd 的 ConfigProvider 包一层桥接组件（ThemeModeProvider 内 useThemeMode → buildTheme(dark)）。

## 二、StatCard 设计公式（tremor / shadcn dashboard 归纳）

参考 tremor 组件库与 shadcn/ui dashboard examples 的统计卡模式，落地规格：

```
┌──────────────────────────┐
│ [icon 40px 圆角方]  标签   │   icon 容器：语义色 12% 底色（color-mix），图标语义色
│                          │   标签 13px text-secondary
│ 28px/700 tabular-nums 值  │   值为 0 时降为 text-tertiary（弱化零值）
└──────────────────────────┘
hover: translateY(-2px) + shadow-card-hover，整卡可点击
```

- `color-mix(in srgb, X 12%, transparent)` 生成任意语义色的浅底，暗色模式同样成立（比手写 rgba 更通用）。
- 数字滚动（CountUp）只在入场/数值变化时动，`prefers-reduced-motion` 下降级。
- 零值视觉降权是 Linear/Vercel 的共同做法——三个大 0 会把真正有事的指标淹没。

## 三、Dashboard 信息架构（2025-2026 共识布局）

```
欢迎区（问候 + 部门 + 日期）
快捷操作（1 行，角色感知：发布任务/发布公告/论坛）
统计卡行（3-4 张，可点击 → 跳转或弹窗）
两栏：主列（待办列表 + 最近动态） / 侧栏（周简报）
≤1024px 折叠单栏
```

- **待办聚合上首页**是本轮最重要 IA 变化：待审核（负责人）与已逾期（全员）直接列表化，每条带类型 Tag + 截止时间，点击跳任务页——参考 Linear「My Issues」与 GitHub Dashboard 的「For you」逻辑：打开第一屏就知道「现在该干什么」。
- 空态必须给「下一步」：EmptyState = 图标落位圆底 + 标题 + 描述 + 可选行动按钮（GitHub/Notion/Linear 三段式）。

## 四、登录页双栏模式

内部工具登录页的克制方案（参考 Vercel/Linear/Supabase 登录页共同结构）：

- 桌面：左 42% 品牌叙事区（渐变底 + 徽标 + 一句话价值主张 + 3 条特性清单）+ 右表单卡（页面底色上浮起的白卡）。
- 移动 ≤900px：品牌区收成顶部横幅（特性清单隐藏），表单全宽。
- 纯 CSS 渐变 + 光斑装饰，不引图片资源（内部工具不值得为登录页背一张 hero 图）。
- 深浅主题下品牌区渐变分别取 `--login-gradient`（variables.css 双份定义）。

## 五、emoji 图标退出 UI 的边界

本轮清理约 45 处后确立的规则：

1. **数据层只存纯文本**（通知标题、指南内容），图标由展示层按类型渲染——旧数据带 emoji 也能正常显示，新数据不再叠加。
2. **语义性 emoji 换 antd 图标**：通知类型/文件类型/奖牌/状态点。文件图标用「统一 FileOutlined + 类型语义色」方案，比每类型一个图标更整洁。
3. **装饰性 emoji 直接删除**（页头、弹窗标题、表单 label）——PageHeader 的 iconBox 已承担视觉锚点。
