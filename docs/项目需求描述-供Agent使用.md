# 学生会线上交流平台 — 项目需求描述

> 本文档用于喂给 AI Agent，作为生成实施计划的输入。目标 Agent 应能基于此文档产出可执行的开发计划。

---

## 一、项目是什么

一个供**高校学生会内部**使用的 Web 应用（PWA），解决部门之间协作靠微信群聊、任务口头传达、信息散落的问题。目前已有版本 v3.2，由一名非计算机专业学生独立开发维护。

- **用户群体**：学生会全体成员（约 50-200 人），分属不同部门
- **角色体系**：volunteer（干事）→ dept_head（部长）→ presidium（主席团）→ president（主席）/ teacher（指导老师）/ developer（开发者）
- **已部署地址**：GitHub Pages（https://yhllxy.github.io/student-union-platform/）

## 二、核心模块（已实现，共 8 个）

### 1. 🔐 认证与权限
- 学生端：姓名 + 学号 + 部门邀请码 → 设密码 → 登录
- 教师端：姓名 + 工号 + 教师邀请码 → 设密码 → 登录
- 角色分级访问控制（前端 + 后端 RLS）
- 忘记密码：邀请码验证 → 自助重置
- 开发者入口：密钥直登管理员账号

### 2. 👥 权限管理（管理员专属）
- 成员列表：查看 / 修改角色 / 调动部门 / 移除成员 / 重置密码
- 邀请码管理：生成 / 停用 / 删除
- 工作看板：每个成员的任务状态分布（待处理/进行中/审核中/已完成/逾期）
- 数据看板：6 类使用事件埋点统计（近 7 天活跃、页面排名、错误日志）

### 3. 📋 任务管理
- 发布任务：标题、内容（Markdown）、优先级、截止时间、执行人、附件、步骤清单（Checklist 语法）、里程碑模式
- 提交任务：填写说明 + 交接备注 → 部长审核（通过/打回）
- 搜索筛选：标题模糊搜索 + 优先级/部门下拉筛选，移动端适配
- 任务可编辑（发布者/管理员）、逾期自动标记、月度报告生成
- 公告一键转为任务

### 4. 📢 部门公告
- 发布/置顶/查看公告，支持附件
- 已读确认：展开即标记已读，统计已读/未读人数，dept_head 可查看具体名单
- 公告转任务（dept_head+）
- Realtime 订阅新公告通知

### 5. 🎫 活动抢票
- 发布票务：活动时间、开抢时间、总票数、每人限抢数
- 抢票 / 退票（活动开始前 5 小时可退）
- 我的票券管理
- Realtime 更新剩余票数

### 6. 💬 部门论坛
- Markdown 发帖 / 回复
- 支持附件上传
- 按部门隔离（仅看本部门帖子）

### 7. 📊 工作台
- 首页仪表盘：统计卡片（任务数/公告数/论坛帖数）+ 部门近期简报
- 个人中心：个人信息 + 部门归属

### 8. 🔔 通用功能
- 通知中心：Realtime 订阅，8 种通知类型（任务分配/审核通过/打回/逾期/公告已读/新公告/论坛回复/抢票成功）
- 全局搜索：跨任务/公告/论坛搜索
- 反馈与建议：Bug 反馈 → 自动写入数据库
- 使用指南：Markdown 文档（新成员上手）
- 侧边栏徽标：任务/公告/论坛未读红点

## 四、架构特点

1. **零后端代码**：所有逻辑在 React 前端 + Supabase 数据库层完成，无中间服务
2. **RLS 安全模型**：Supabase Row Level Security 保证数据隔离（如论坛按部门、任务按创建者/执行人）
3. **Realtime 驱动**：通知、任务、公告、票务等模块通过 Supabase Realtime 实时更新，无需轮询
4. **PWA 可安装**：手机端添加到主屏幕，全屏 App 体验，离线可用
5. **移动端优先**：所有页面响应式适配（Drawer 替代 Sider、Table scroll.x、Modal 宽度适配）

## 六、关键约束

1. **零外部依赖**：不接 Google Analytics / 第三方服务，数据全在 Supabase
2. **fire-and-forget 模式**：监控/埋点类操作不能阻塞用户交互
3. **降级兜底**：新功能加载失败时核心功能不受影响
4. **单开发者维护**：代码要简洁、模块化，文件超过 500 行就要拆分
5. **移动端必须可用**：手机端是主要使用场景
