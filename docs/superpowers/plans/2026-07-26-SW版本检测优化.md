# Service Worker 版本检测优化 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 优化 Service Worker 版本检测逻辑：SW 更新发现时同步拉取 changelog（而非等到页面刷新），缩短轮询间隔，并让 React 能响应 SW 更新事件。

**Architecture:** 在 `index.html` 中让 `trackUpdate()` 同时触发 `checkVersion()`（拉取 version.json → 存 localStorage），这样 React 端 `useVersionNotification` 能在下次挂载时读到 changelog。利用 `controllerchange` 事件通知 React 自动刷新。缩短 SW 更新轮询从 60 分钟到 10 分钟。

**Tech Stack:** Service Worker API + localStorage IPC + React hooks

## 当前问题分析

现有代码 `index.html` 的逻辑：

1. **SW 注册时** → `trackUpdate(registration)` → 监听 `updatefound` → 显示 toast "新版本已就绪，点击刷新"
2. **页面加载时** → `checkVersion()` → 拉取 `version.json` → 对比 localStorage 的 `pwa_last_version` → 存到 `pwa_new_version` → React 挂载后读取并弹通知
3. **每 60 分钟** → `registration.update()` → 触发 SW 下载

**三个问题：**

| 问题 | 影响 |
|------|------|
| SW 更新 toast 只有"新版本已就绪"提示，**没有 changelog** | 用户点刷新后 React 重新挂载，`useVersionNotification` 才读 localStorage 弹 changelog。相当于用户先看到 toast → 刷新 → 才看到更新内容。用户体验割裂 |
| 60 分钟轮询太长 | 紧急 Bug 修复部署后，用户可能用 50+ 分钟的旧版本 |
| `controllerchange` 事件后没有通知 React 检查版本 | `skipWaiting()` + `clients.claim()` 后 SW 已激活，但 React 不知道——除非页面刷新 |

---

## 风险评估与危险预案

| 风险 | 严重度 | 预案 |
|------|--------|------|
| `checkVersion()` 在非 React 上下文中写入 localStorage，可能和 React 同时读写冲突 | 🟢 低 | `localStorage` 在浏览器中是同步 API，同一 JS 线程不会冲突。且 `checkVersion()` 写入 `pwa_new_version`，React 的 `useVersionNotification` 在 `useEffect` 中一次性读取后立即 `removeItem`，时序安全 |
| 缩短轮询到 10 分钟增加网络请求（`registration.update()` + `checkVersion()` 各一次） | 🟢 低 | 两个请求的总大小 < 2KB（SW.js 检查用 HTTP 304 返回，version.json ~200B）。10 分钟一次 ≈ 每天 144 次请求，GitHub Pages 免费额度足够 |
| `controllerchange` 监听可能导致意外刷新 | 🟡 中 | 不在 `controllerchange` 中强制 `location.reload()`，而是用 Ant Design `notification` 提示用户手动刷新（与现有 toast 行为一致） |

### Task 1: 优化 `index.html` 的 SW 注册逻辑

- [ ] **Step 1: 修改 trackUpdate — 联动 checkVersion**

当前 `trackUpdate()` 只是显示 toast。改造为：显示 toast + 同步拉取 changelog：

将 [index.html:54-71](index.html#L54-L71) 的 `trackUpdate` 函数替换为：

```javascript
// 监听 SW 更新
function trackUpdate(registration) {
  if (!registration) return;
  // 已有 waiting 状态的 SW（首次访问时 SW 已在等待激活）
  if (registration.waiting) {
    newWorker = registration.waiting;
    checkVersion();  // ← 新增：同步拉取 changelog
    showUpdateToast();
  }
  // 监听新 SW 安装
  registration.addEventListener('updatefound', function () {
    var installing = registration.installing;
    if (!installing) return;
    installing.addEventListener('statechange', function () {
      if (installing.state === 'installed' && navigator.serviceWorker.controller) {
        newWorker = installing;
        checkVersion();  // ← 新增：同步拉取 changelog
        showUpdateToast();
      }
    });
  });
}
```

```javascript
function showUpdateToast() {
  if (!updateToast) return;
  updateToast.style.display = 'block';
  updateToast.onclick = function () {
    updateToast.style.display = 'none';
    // 通知 waiting SW 跳过等待、立即激活

      newWorker.postMessage({ type: 'skipWaiting' });  // 小写，匹配 sw.js:146

    // 刷新页面让 React 读取 changelog
    window.location.reload();
  };
}
```

### Task 2: 优化 `useVersionNotification.ts` — 响应 SW 激活

**Files:**
- Modify: `src/hooks/useVersionNotification.ts`

- [ ] **Step 1: 新增 controllerchange 监听**

在 `useVersionNotification.ts` 的 `useEffect` 中（第 48 行后），增加 `controllerchange` 监听，让 SW 激活后 React 自动重新检查版本：

在 useEffect 的返回清理函数前插入：

```typescript
// ---- ③ 监听 SW 激活（controllerchange） ----
// 当用户点击"新版本已就绪"后，SW skipWaiting→activate→controllerchange 触发
// 此时重新检查 localStorage 中是否有新版本 changelog
const onControllerChange = () => {
  try {
    const raw = localStorage.getItem(NEW_VERSION_KEY);
    if (raw) {
      const data: VersionData = JSON.parse(raw);
      const lastVer = localStorage.getItem(LAST_VERSION_KEY);
      if (data.version && data.version !== lastVer) {
        const changelogText = data.changelog?.length
          ? data.changelog.map((c, i) => `${i + 1}. ${c}`).join('\n')
          : '请查看应用最新变化';

        notification.info({
          message: `📢 平台已更新至 ${data.version}`,
          description: changelogText,
          duration: 8,
          placement: 'topRight',
          style: { whiteSpace: 'pre-line' },
        });

        localStorage.setItem(LAST_VERSION_KEY, data.version);
      }
      localStorage.removeItem(NEW_VERSION_KEY);
    }
  } catch {
    // 静默降级
  }
};

navigator.serviceWorker?.addEventListener('controllerchange', onControllerChange);
```

并在 return 清理函数中移除监听器。将现有的 return：

```typescript
return () => window.removeEventListener('beforeinstallprompt', handler);
```

改为：

```typescript
return () => {
  window.removeEventListener('beforeinstallprompt', handler);
  navigator.serviceWorker?.removeEventListener('controllerchange', onControllerChange);
};
```

- [ ] **Step 2: 注意重复通知问题**

现在有两个地方可能弹版本通知：
1. `useVersionNotification` 中的 `useEffect` 初始化检查（页面加载时）
2. 新增的 `controllerchange` 监听（SW 激活时）

这两个场景是互斥的：
- 场景 1：用户直接打开/刷新页面 → `useEffect` 中读到 `pwa_new_version` → 弹通知 → 清除 key
- 场景 2：用户在使用中，SW 更新被发现 → 点击 toast 刷新 → `controllerchange` 触发 → `onControllerChange` 中读 `pwa_new_version` → 弹通知

场景 2 中，`controllerchange` 触发后页面会 `reload()`，然后场景 1 的 `useEffect` 也会触发。但 `controllerchange` 的 `onControllerChange` 已经把 `pwa_new_version` 读走并清除了，所以 `useEffect` 不会弹第二次。
