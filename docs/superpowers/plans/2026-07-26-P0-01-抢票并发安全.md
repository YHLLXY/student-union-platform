# P0-01 抢票并发安全 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 `grabTicket()` 从"SELECT+INSERT"两步分离改为 PostgreSQL RPC 原子操作，用 `FOR UPDATE` 行锁消除 TOCTOU 竞态条件，杜绝超卖。

**Architecture:** 在 Supabase 数据库创建 `grab_ticket` RPC 函数（`SECURITY DEFINER`），把校验+插入包成一个事务，行锁串行化对同一票务的并发请求。前端 `grabTicket()` 改为一行 `supabase.rpc()` 调用。

**Tech Stack:** PostgreSQL plpgsql + Supabase RPC + TypeScript

## 风险评估与危险预案

| 风险 | 严重度 | 预案 |
|------|--------|------|
| RPC 未在 Supabase Dashboard 执行 | 🔴 高 | 部署前必须人工执行 SQL。如果 RPC 不存在，`supabase.rpc('grab_ticket', ...)` 会返回 "function not found" 错误，`grabTicket` 会降级返回"抢票失败，请重试"，不会导致前端崩溃 |
| `FOR UPDATE` 行锁等待超时 | 🟡 中 | PostgreSQL 默认 `idle_in_transaction_session_timeout` 下锁等待无上限，但我们的 RPC 执行时间 <50ms。如果极罕见情况下超时，PostgreSQL 抛 `lock_not_available` 错误 → 走 EXCEPTION 分支 → 返回"抢票失败，请重试" |
| 旧 `grabTicket` 的调用方 `TicketList.tsx` 依赖返回值格式 | 🟢 低 | RPC 返回 `{ success: boolean, message: string }` JSONB，与现有返回值完全一致，调用方无需修改 |
| 并发量极低（50-200人）可能觉得此任务不需要 | 🟢 低 | 但抢票场景本身就是突发并发（开抢瞬间多人同时点），应该先修。即使并发低，"SELECT+INSERT"分离本身就是不正确的模式 |

- [ ] **Step 1: 在 `supabase-migration.sql` 末尾追加 RPC**

在文件末尾追加以下内容：

```sql
-- ============================================================
-- 第十四部分：抢票并发安全 RPC（P0-01）
-- ============================================================

CREATE OR REPLACE FUNCTION grab_ticket(
  p_ticket_id UUID,
  p_user_id UUID,
  p_student_id TEXT,
  p_name TEXT
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public
AS $$
DECLARE
  v_ticket RECORD;
  v_my_count INTEGER;
  v_total_grabbed INTEGER;
BEGIN
  -- 1. 锁定票务行（FOR UPDATE 串行化并发请求，消除 TOCTOU）
  SELECT * INTO v_ticket
  FROM tickets
  WHERE id = p_ticket_id
  FOR UPDATE;

  IF NOT FOUND THEN
    RETURN jsonb_build_object('success', false, 'message', '票务不存在');
  END IF;

  -- 2. 检查是否到开抢时间
  IF v_ticket.open_time > now() THEN
    RETURN jsonb_build_object('success', false, 'message', '尚未到开抢时间');
  END IF;

  -- 3. 检查用户已抢数量（在同一事务内，count 不受并发插入影响）
  SELECT count(*) INTO v_my_count
  FROM ticket_records
  WHERE ticket_id = p_ticket_id AND user_id = p_user_id;

  IF v_my_count >= v_ticket.per_user_limit THEN
    RETURN jsonb_build_object('success', false, 'message', '每人限抢 ' || v_ticket.per_user_limit || ' 张');
  END IF;

  -- 4. 检查剩余票数
  SELECT count(*) INTO v_total_grabbed
  FROM ticket_records
  WHERE ticket_id = p_ticket_id;

  IF v_total_grabbed >= v_ticket.total_count THEN
    RETURN jsonb_build_object('success', false, 'message', '票已被抢完');
  END IF;

  -- 5. 插入抢票记录
  INSERT INTO ticket_records (ticket_id, user_id, student_id, name)
  VALUES (p_ticket_id, p_user_id, p_student_id, p_name);

  RETURN jsonb_build_object('success', true, 'message', '抢票成功！');

EXCEPTION
  WHEN unique_violation THEN
    -- UNIQUE(ticket_id, user_id) 约束冲突 = 重复抢票
    RETURN jsonb_build_object('success', false, 'message', '你已抢过该票');
  WHEN OTHERS THEN
    RETURN jsonb_build_object('success', false, 'message', '抢票失败，请重试');
END;
$$;
```

```typescript
/** 抢票（RPC 原子操作，FOR UPDATE 行锁防并发超卖） */
export async function grabTicket(
  ticketId: string,
  userId: string,
  studentId: string,
  name: string,
): Promise<{ success: boolean; message: string }> {
  const { data, error } = await supabase.rpc('grab_ticket', {
    p_ticket_id: ticketId,
    p_user_id: userId,
    p_student_id: studentId,
    p_name: name,
  });

  if (error) {
    log.error('grab_ticket RPC 调用失败', error);
    return { success: false, message: '抢票失败，请重试' };
  }

  const result = data as { success: boolean; message: string };
  return result;
}
```
