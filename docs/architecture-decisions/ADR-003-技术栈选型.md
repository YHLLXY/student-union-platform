# ADR-003: 选择 React + TypeScript + Ant Design + Vite

- **状态:** 已采纳
- **日期:** 2025-06（项目启动）+ 2026-07（重大重构 v2）
- **决策者:** 余翰林（独立开发者）

## 上下文

项目经历了两次重大技术选型变更：

- **v1（2025-06 ~ 2026-06）：** jQuery + HTML + CSS，纯静态页面。快速原型，给学生会的学长看效果。
- **v2（2026-07）：** 全量重写为 React 19 + TypeScript 6 + Ant Design 6 + Vite 8 + Supabase。原因：v1 的代码已经无法维护（大量重复 DOM 操作，无状态管理，无类型检查）。

## 决策

| 技术 | 选择 | 替代方案 | 理由 |
|------|------|----------|------|
| 框架 | React 19 | Vue, Svelte | 生态最大，Ant Design 绑定 React |
| 类型 | TypeScript 6 | JavaScript | Supabase 返回类型复杂，无类型极易出 Bug |
| UI 库 | Ant Design 6 | Material UI, shadcn/ui | 中文企业级生态最好，Table/Form/Modal 开箱即用 |
| 构建 | Vite 8 | webpack, CRA | 开发服务器秒启动，HMR 快 |
| 后端 | Supabase | Firebase, 自建 | 见 ADR-001 |

## 后果

### 正面
- TypeScript 在编译期捕获了数十个潜在 Bug
- Ant Design 的 Table/Form/Select/DatePicker 大幅减少手写 UI 代码
- Vite 的开发体验远超 webpack（1 秒 vs 30 秒启动）

### 负面
- Ant Design 6 的 bundle 较大（约 200KB gzipped），首屏加载需要优化
- React 的学习曲线对继任者有挑战
- TypeScript 的严格类型检查在开发中偶尔让人沮丧——但换来了运行时安全

### 缓解措施
- `React.lazy()` + `Suspense` 分包加载，减少首屏体积
- PWA Service Worker 缓存让二次访问几乎秒开
