# ADR-002: 选择 PWA 作为客户端形态

- **状态:** 已采纳
- **日期:** 2025-06（项目启动时）
- **决策者:** 余翰林（独立开发者）

## 上下文

学生会成员使用手机为主。需要一个能在手机上"像 App 一样"使用的方案。

评估的方案：
1. **React Native / Flutter** — 原生 App
2. **微信小程序** — 国内最流行的轻应用方案
3. **PWA**（Progressive Web App）— 网页应用 + Service Worker + 可安装

## 决策

选择 **PWA**。

## 理由

| 维度 | PWA | 小程序 | 原生 App |
|------|-----|--------|----------|
| 开发成本 | 和写网页一样 | 需要学 WXML/WXSS | 需要学 RN/Flutter |
| 分发 | 网址即用，无需审核 | 需要微信审核 | 需要应用商店上架 |
| 更新 | 刷新即更新 | 审核周期 1-7 天 | 审核周期 1-3 天 |
| 离线能力 | Service Worker 缓存 | 有限 | 可以 |
| 推送通知 | Web Push（iOS 17.4+ 才支持） | 订阅消息 | 原生推送 |

核心考量：
- **更新频率：** 学生会平台频繁迭代（v1 → v3.2），每周几次更新。小程序/App 审核周期会严重影响响应速度
- **维护负担：** 单人开发，维护三套代码（Web + iOS + Android）不可行
- **分发：** 二维码发到微信群 → 浏览器打开 → 添加到主屏幕，比"去应用商店下载"简单得多
- **iOS 安装：** iOS 17.4 起 Safari 支持 PWA 安装提示，之前的版本需要用户手动"添加到主屏幕"

## 后果

### 正面
- 一套代码跑所有平台（PC + iOS + Android）
- 更新即时生效，不需要审核
- Service Worker 离线缓存让基本功能在没有网络时也能打开

### 负面
- iOS Safari 对 PWA 的支持不如 Android Chrome 完善（如 Web Push 直到 iOS 17.4 才支持）
- 微信内置浏览器不会触发 PWA 安装提示，需要引导用户用系统浏览器打开
- 不能用原生硬件功能（蓝牙、NFC等）——但学生会平台不需要

### 缓解措施
- `index.html` 中保留 `beforeinstallprompt` 兜底 + 手动安装按钮
- 使用指南中指导用户用 Safari/Chrome 打开并添加到主屏幕
