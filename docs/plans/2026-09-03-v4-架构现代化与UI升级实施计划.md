> 执行：接手 agent · 2026-09-03 · 全程自主实施

## 零、摸底结论（改造依据）

### Bundle 审计（v3.6 基线，rolldown sourcemap 分析）

| Chunk | 体积 | 内容 | 问题 |
|---|---|---|---|
| `SkeletonBlocks-*.js` | **801KB** | react-dom(533KB源) + antd(450KB) + Supabase SDK(约800KB源) | vendor 被归并进以业务组件命名的共享 chunk，且位于首屏关键路径 |
| `index-*.js` | 448KB | antd 另一半 + react-router + motion-dom + framer-motion | antd 被撕裂、motion 进了入口 |
| `TrophyOutlined-*.js` | 152KB | antd Table + Tree | vendor 以图标组件命名 |
| `PostList-*.js` | 130KB | react-markdown 全家桶 | 懒加载，可接受 |

根因：Vite 8/Rolldown 无 `manualChunks`，自动分包把「被入口+懒加载页共享」的 vendor 塞进了首个共享模块命名的 chunk。

### 代码层结论

- 服务层 11 个 service 全部「吞错返回 []/null/false」，调用方无法区分空数据与失败；
- 服务层大量 `as unknown as X` 强转，无数据库类型；
- 读路径全部为 `useEffect + useState + skeleton` 手写样板；
- UI 遗留债（v3.6 总结）：emoji 图标约 20 处、Dashboard 信息架构、AnalyticsDashboard 内联样式、LoginPage 580 行单文件。

## 一、Phase A：底层架构

### A1. Vendor 分包（vite.config.ts）
- 采用 rolldown `output.codeSplitting.groups`（本机 rolldown 版本中 `advancedChunks` 已 deprecated）；
- 分组：`react-core`(react/react-dom/scheduler) → `supabase`(@supabase/*) → `antd`(antd/@ant-design/@rc-component/rc-*) → `motion`(motion/motion-dom/motion-utils/framer-motion) → `markdown`(react-markdown/micromark/unified 系列)；
- Windows 正则用 `[\\/]` 匹配路径分隔符；priority 明确排序防误捕获；
- 验收：构建后 chunk 命名语义化、antd 不再撕裂、首屏关键路径可预期。

### A2. 数据库类型（src/types/database.ts）
- 以 supabase-migration.sql 为唯一事实来源，手写 14 张表的 Row/Insert/Update + Relationships；
- `supabaseClient.ts` 改为 `createClient<Database>`；
- 服务层逐步消除 `as unknown as`（嵌套 select 改用外键别名推断）。

### A3. 服务层错误约定统一（src/lib/sb.ts）
- 新增 `unwrap()` 帮助函数：查询失败 → logger 记录 + 抛 `SbError`；
- 所有 service 读函数改为「失败即抛」，调用方一律由 A4 的 isError 或 catch 接住；
- 铁律：任何页面不允许出现「查询失败静默渲染空列表」。

### A4. TanStack Query v5 数据层
- `QueryClientProvider`：staleTime 30s、gcTime 5min、retry 1、refetchOnWindowFocus false（贴近现行行为，降低回归面）；
- 迁移读路径：Dashboard、TaskListPage（realtime → invalidateQueries；看板拖拽乐观更新改 setQueryData）、NoticeList、SchoolNoticeList、PostList、TicketList、MyTickets、ProfilePage、MemberManage、WorkOverview、AnalyticsDashboard、NotificationBell；
- 变更类操作（create/update/delete）维持既有命令式流程，成功后 invalidateQueries。

### A5. 路径别名 `@/`
- tsconfig.app.json paths + vite resolve.alias；
- 全量改写 src 内相对 import（脚本生成映射，tsc 验证）。

### A6. 认证健壮性
- App.tsx 挂 `onAuthStateChange`：SIGNED_OUT/TOKEN_REFRESHED 失败等场景收敛登录态，修复「会话过期后页面僵尸」问题。

## 二、Phase B：UI 升级

### B1. 通用组件（src/components/common/）
- `StatCard`：图标容器 + 数字（CountUp）+ 标签 + 语义色 + hover 抬升 + 可点击，参考 tremor/shadcn dashboard 公式；
- `EmptyState`：图标 + 标题 + 描述 + 可选行动按钮，替换 11 处裸 `Empty`；
- `PageHeader`：标题 + 副标题 + 右侧操作区，统一页头（emoji 清理承接）。

### B2. Dashboard 信息架构 v2
- 布局：欢迎区 → 快捷操作 → 统计卡行（可点击）→ 主列（待办聚合：待审核列表/逾期任务 + 最近动态）+ 侧栏（周简报）；
- 待审核/逾期直接列表化上首页（数据源已有，补 service 查询）。

### B3. LoginPage 拆分与视觉升级
- 拆为 `AuthShell`（品牌区+表单容器）/`StudentAuthPanel`/`TeacherAuthPanel`/`PasswordStep`/`ForgotStep`；
- 视觉：左侧品牌叙事区（渐变+价值点），右侧表单卡；移动端上下堆叠；纯 CSS 实现，不引图片资源。

### B4. 暗色模式
- `ThemeModeProvider`：light/dark/system 三态，localStorage 持久化 + 跟随 `prefers-color-scheme`；
- antd `theme.darkAlgorithm` 动态挂载；variables.css 增加 `[data-theme='dark']` 全量覆盖；`<html data-theme>` 同步；
- Header 用户菜单内加切换项；修正 manifest.json `theme_color`（现错为 #1677ff）。

### B5. Admin 与杂项
- AnalyticsDashboard 样式模块化（去内联）+ StatCard 接入；
- emoji → @ant-design/icons 全量替换（约 20 处）；
- TaskListPage 视图切换接入 motion `AnimatePresence`（经封装层）。
