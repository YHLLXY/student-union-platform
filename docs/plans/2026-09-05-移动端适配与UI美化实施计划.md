- 方法:应用内浏览器 390×844(iPhone 级)与 360×780(小屏 Android 级)视口,暗色+亮色两模式,

## 二、P0 移动端修复(6 项)

1. **论坛分类 chips 化**:`PostList.tsx` 用 `Grid.useBreakpoint()` 的 `md` 门控(项目既有模式,
   TaskListPage/AppLayout 同款):≥md 渲染现有侧栏 Menu,<md 在 PageHeader 下方渲染横向滚动 chips
   (`.categoryChips`,overflow-x auto + nowrap,触控高 36px,选中态 `--color-primary` 底白字)。
   新增样式全走 token。
2. **iOS 16px 输入**:`base.css` 追加 ≤768px 媒体查询:`input.ant-input / textarea.ant-input /
   .ant-input-affix-wrapper>input / .ant-select-selection-search-input / .ant-picker-input>input`
   font-size 16px(!important 覆盖 antd 默认)。副作用仅"移动端输入文字变大",可接受且更易读。
3. **统计卡孤儿行**:`dashboard.module.css` 与 `profile.module.css` 的移动端 statsRow 网格追加
   `.statsRow > *:last-child { grid-column: span 2; }`(两个页面均为 3 卡,末卡跨双列填满行;
   附注释说明"若未来卡数变更需复核")。
4. **权限管理表移动端**:`MemberManage.tsx` 学号/工号列加 `md` 门控(<md 不渲染该列);
   `admin.module.css` ≤768px `:global` 收紧 .ant-table 单元格 padding 16→10px。
   操作列仍在末尾,残留少量滚动可接受(不引入 fixed 列,避免移动端 fixed 列阴影/同步 bug)。
5. **空态文案**:`NoticeList.tsx:147` 改为"点击上方「发布公告」发布第一条公告"。
6. **触控目标**:`auth.module.css` `.devEntry` 按钮 min-height 40px。

## 三、P1 UI 美化(调用 redesign-existing-projects skill 审计驱动,定向小步)

既有 token 体系完备(variables.css:阴影/圆角/动效/触控/安全区),美化的主体是**把游离于体系外的
残留收敛回去 + 补齐微交互**,不改变信息架构与视觉主体:

1. **阴影收敛**:10 处硬编码 box-shadow(profile×3、notices、tasks、tickets、global-search、forum、
   dashboard、school)按视觉强度映射到 var(--shadow-sm/md/lg/card/card-hover),
   颜色随主题自动切换(暗色不再出现亮底黑影)。
2. **圆角收敛**:34 处硬编码 border-radius 就近映射 var(--radius-sm/md/lg/xl)(逐处核对,不改变视觉等级)。
3. **数字排版**:statValue 与管理表格数字列 `font-variant-numeric: tabular-nums`(数据加载/刷新时数字不跳动)。
4. **按压反馈**:可交互卡片(任务卡/帖子卡/统计卡)` :active` 轻微下沉(scale 0.995 级),
   transition 仅 transform/opacity,尊重 prefers-reduced-motion(复用既有动效基座变量)。
5. **过渡统一**:顺手把 hover 过渡的硬编码 `0.2s ease` 换 var(--transition-normal)(仅同值替换)。

## 四、不做清单

- 不换字体、不引入任何新依赖、不改信息架构/页面结构、不动 header 品牌渐变与登录页视觉主体。
- 不加 backdrop-blur / 噪点 / 玻璃拟态(移动端 GPU 重绘成本,与 v4.1 性能成果冲突)。
- 不给表格加 fixed 列(antd 移动端 fixed 列阴影同步已知问题,收益不抵风险)。
- 不动 v4.1 性能架构(SW/懒加载/分包);美化仅 CSS + 少量 JSX 门控,不加急加载体积。

## 六、自审记录

1. **P0-1 修正**:原设想"≤768px 把 Menu 切 horizontal"——antd 水平 Menu 无横向滚动、6 项在 360px 会溢出,
   改为自绘 chips(也顺便获得选中态token化与 36px 触控高)。
2. **P0-3 修正**:`.statsRow` 子元素是动效包裹层(FadeIn),span 2 落在包裹层上即可生效(grid item 看包裹层);
   需确认 dashboard/profile 的 statsRow 在移动端确实已是 grid(已确认:242 行/460 行)。
3. **P0-4 修正**:列门控必须放在 columns 定义处并保持 hooks 规则(md 来自 useBreakpoint,无 hooks 顺序问题)。
4. **P1-1 风险**:global-search.module.css 的 0 6px 24px 0.15 强于 --shadow-lg(0 6px 24px 0.12),
   统一到 --shadow-lg 会让浮层影子略浅——可接受(浮层本身有遮罩);记录为有意决策。
5. **P1-2 风险**:34 处圆角需逐处看值,防止把"故意的小圆角"(如 4px 徽标)错收成 --radius-sm(6px);
   执行时按"值相等就近映射,值不等则保留"原则,不硬凑。
6. **测试环境声明**:发版产物必须用真实 .env 构建,stub 仅本地;提交前确认 dist 不入库(本就 gitignore)。
