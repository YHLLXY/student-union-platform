# 学生会线上交流平台 — 完整项目审查材料

> **场景：** 这是一个已上线的高校学生会内部管理 Web 应用（PWA），由 1 名非计算机专业学生独立开发。请基于以下材料对该项目进行全面审查，给出改进建议。
>
> **审查要求：**
> - 指出架构设计、数据库、安全、性能、代码质量、可维护性等方面的问题和改进方向
> - 区分"必须修复"和"可以优化"两个优先级
> - 考虑约束条件：单人维护、用户 50-200 人、数据不敏感、移动端优先
> - 不要建议"用专业团队重写"之类不现实的方案

## 一、项目概况

- **定位：** 高校学生会内部线上协作平台，替换微信群聊式管理
- **用户：** 12 个部门 × 约 50-200 名成员
- **部署：** GitHub Pages（静态托管）+ Supabase（BaaS 后端）
- **技术栈：** React 19 + TypeScript 6 + Ant Design 6 + Vite 8（Rolldown 打包）
- **后端：** Supabase（PostgreSQL + Auth + Storage + Realtime）
- **PWA：** Service Worker 离线缓存、全屏 App、版本更新通知
- **当前版本：** v3.2（已迭代 15+ 个版本）
- **已部署：** https://yhllxy.github.io/student-union-platform/

## 二、完整数据库 Schema（15 张表）

```sql
-- 1. 用户表
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  auth_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  student_id TEXT UNIQUE NOT NULL,
  department TEXT NOT NULL DEFAULT '',
  role TEXT NOT NULL DEFAULT 'volunteer',
  avatar_url TEXT,
  created_at TIMESTAMPTZ DEFAULT now()
);

-- 2. 邀请码表
CREATE TABLE invite_codes (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  code TEXT UNIQUE NOT NULL,
  department TEXT NOT NULL,
  role TEXT NOT NULL DEFAULT 'volunteer',
  is_used BOOLEAN DEFAULT false,
  used_by UUID REFERENCES users(id),
  created_at TIMESTAMPTZ DEFAULT now()
);

-- 3. 任务表
CREATE TABLE tasks (
  id, title, content, priority(TEXT), status(TEXT),
  deadline, created_by→users, assigned_to→users,
  assigned_department, has_milestones(BOOL),
  collaborating_departments(JSONB),
  handover_note, linked_notice_id,
  attachments(JSONB),
  created_at, updated_at
);

-- 4. 任务提交记录表
CREATE TABLE task_submissions (
  id, task_id→tasks(CASCADE), user_id→users,
  note, status, review_note,
  submitted_at, reviewed_at
);

-- 5. 里程碑表
CREATE TABLE milestones (task_id→tasks(CASCADE), title, due_date, completed_at, ...);

-- 6. 部门公告表
CREATE TABLE notices (id, title, content, type, department, is_pinned, created_by→users, attachments(JSONB), ...);

-- 7. 校级通知表
CREATE TABLE school_notices (id, title, content, is_pinned, created_by→users, ...);

-- 8. 通知中心表
CREATE TABLE notifications (
  id, user_id→users, type(TEXT), title, body,
  is_read, related_task_id, related_notice_id, related_forum_id,
  created_at
);

-- 9. 公告已读表
CREATE TABLE notice_reads (notice_id, user_id, read_at);

-- 10. 论坛帖子表
CREATE TABLE forum_posts (id, title, content, category, department, author_id→users, attachments(JSONB), ...);

-- 11. 论坛回复表
CREATE TABLE forum_replies (post_id→forum_posts(CASCADE), author_id→users, content, ...);

-- 12. 票务表
CREATE TABLE tickets (
  id, title, total_count, remaining_count, per_user_limit,
  event_time, open_time, created_by→users, ...
);

-- 13. 票务抢票记录表
CREATE TABLE ticket_records (ticket_id→tickets, user_id→users, refunded, ...);

-- 14. 反馈表
CREATE TABLE feedbacks (user_id→users, content, status, created_at);

-- 15. 使用事件埋点表（v3.2 新增）
CREATE TABLE usage_events (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  event_type TEXT NOT NULL,    -- page_view | login | task_complete | notice_read | ticket_action | error
  user_id UUID REFERENCES auth.users(id) ON DELETE SET NULL,
  module TEXT, action TEXT,
  metadata JSONB DEFAULT '{}',
  created_at TIMESTAMPTZ DEFAULT now()
);
-- 索引：idx_usage_type_time(event_type, created_at DESC), idx_usage_user(user_id)
```

### 3.2 认证流程

```
App.tsx
  ├─ getCurrentUser() 查询本地 session → 有 → 直接进入
  └─ 无 → <LoginPage>
        ├─ 学生：姓名 + 学号 + 邀请码 → checkStudentId()
        │   ├─ 已注册 → 输入密码 → signIn()
        │   └─ 新用户 → checkInviteCode() → 设密码 → signUp()
        └─ 教师：同理，但用教师邀请码 + signUpTeacher()
```

Auth 状态通过 `AuthContext`（React Context）全局注入，各组件通过 `useAuth()` hook 获取当前用户。

### 3.3 权限模型

```typescript
// 角色层级（数字越大权限越高）
const ROLE_LEVEL = {
  volunteer: 0,    // 常驻志愿者
  dept_head: 1,    // 部门负责人
  presidium: 2,    // 主席团成员
  president: 3,    // 主席
  teacher: 3,      // 指导老师
  developer: 3,    // 开发者
};

// 前端权限判断
function hasMinRole(userRole, requiredRole): boolean
function isAdmin(role): boolean  // president | teacher | developer

// 后端权限：Supabase Row Level Security (RLS)
// 例：任务表 — 仅本部门可读，仅创建者可更新
```

**权限检查是双重的：** 前端 `hasMinRole` 控制 UI 显隐 + Supabase RLS 控制数据库访问。

### 3.5 实时通知架构


### 3.7 PWA 缓存策略

```
Service Worker 缓存策略：
  HTML（导航请求） → 网络优先，回退缓存
  JS/CSS/图片      → 缓存优先，回退网络
  Supabase API     → 仅网络，不缓存（确保数据实时）

版本更新：改 CACHE_VERSION → skipWaiting → activate 清理旧缓存 → clients.claim
部署时自动推送新版本通知（60 分钟轮询检查 / 手动刷新时检测）
```

## 六、关键设计决策（开发者的取舍）

| 决策 | 选择 | 理由 |
|------|------|------|
| 后端 | Supabase（零中间服务） | 单人维护，不写后端代码 |
| 前端权限 | 双重控制（hasMinRole + RLS） | 前端做 UX 优化（隐藏不可用按钮），RLS 做最终数据保护 |
| 注册方式 | 邀请码（无邮箱/手机） | 学生会没有成员邮箱数据库，邀请码通过微信群分发最方便 |
| 埋点模式 | fire-and-forget，无重试 | 用户量小、数据不关键，无需队列+重试的复杂度 |
| 任务提交 | 先提交 → 部长审核 → 通过/打回 | 仿照企业 OA 审批流，而非简单的"标记完成" |
| 公告已读 | 展开即标记已读 + 统计已读/未读 | 比微信群"收到请回复"更可靠 |
| 票务抢票 | 乐观更新 + Realtime | 减少 API 调用，剩余票数实时同步 |
| 密码重置 | 邀请码验证 → 自助重置 | 不需要管理员介入 |
| 开发者入口 | 密钥填入表单 → 仍需输入密码 | 快速切换账号，不是免密登录 |
| 文件存储 | Supabase Storage + attachments JSONB | 避免自己搭文件服务 |

## 七、当前已知问题与限制

1. **`FileUpload.tsx` 打包体积 35KB**（项目最大的单个组件），可能包含重复工具函数
2. **`helpers.ts` 打包体积 778KB** — 因为依赖了 dayjs（日期库），对 PWA 首屏加载有影响
3. **GitHub Pages 不返回自定义 HTTP 头**，Service Worker 的 `Service-Worker-Allowed` 无法配置
4. **Supabase `PromiseLike` 类型问题** — postgrest-js 返回的不是标准 `Promise`，不能用 `.catch()`，需用 `async/await + try-catch` 包装
5. **PWA 版本更新** — 目前 60 分钟轮询检查，不如 `updatefound` 事件及时
6. **数据看板 `activeUsers7d`** 使用客户端 `new Set()` 做 DISTINCT 去重——数据量大后会成为瓶颈（但当前数据量完全够用）
