## 经验（接续 v4.6.0 的 17，本轮 18–24）

### 18. 响应式收口往往要两轮：第一轮修「配置」，第二轮修「内容与行」

第一轮（#7 一次）按 checklist 修了能枚举的配置项（Table scroll.x、Modal width、显式 flex 容器断点），自认为收敛了；两个月后用户仍说「很多地方要左右滑」。残留的三类全在 checklist 之外：**用户生成内容**（长 URL/代码块——上轮种子数据里根本没有）、**内联样式行**（`style={{display:'flex'}}` 不走 CSS 文件，媒体查询管不到）、**组件库内部规则**（antd 卡头的 nowrap+ellipsis）。
**避免**：判断「适配做完没有」不能靠枚举代码点，要靠在目标视口下实测。本轮把实测固化成门禁，第三轮才会真正消失。

### 19. 找「页面级溢出」先找真正的滚动器，否则门禁全程假绿

本项目的纵向滚动器是 `.contentArea`（`overflow-y:auto`），而 CSS 规范规定 `overflow-y:auto` 会把 `overflow-x` **隐式计算为 auto**——页面内容超宽时表现为内容区内部横滚，`document.scrollingElement.scrollWidth` 永远是 375，量它全程假绿。同理弹窗遮罩 `.ant-modal-wrap`（fixed + overflow:auto）是弹窗内容溢出的真实滚动器。
**做法**：门禁量三层——`document.scrollingElement`（登录页等布局外页面）+ `.ant-layout-content`（登录后）+ `.ant-modal-wrap`（打开中的弹窗）；同时**有意豁免**嵌套的有意横滚容器（表格 scroll.x、看板、热力图）——判定在滚动器层做，诊断输出才做元素级。

### 20. 自定义 CSS 没有全局 box-sizing 重置时，`max-width:100%` 不是上限

登录页超宽 10px 的根因挖了三层：`.loginCard` 宽度是 `min(400px,100%)` 也照样超——因为本项目只有 antd 组件自带 border-box 重置，**普通 div 默认 content-box**，`100%` 之后 padding+border 再叠加。这颗雷埋了 20 轮迭代，直到有元素恰好「卡在刚好超一点」的尺寸上才炸。
**做法**：本轮只给踩雷元素点状补 `box-sizing:border-box`（安全、可审查）；全局 `*{box-sizing:border-box}` 重置记 ISSUES #19 留专项做——它会改变全部既有盒子的尺寸语义，桌面端可能有可见位移，混在适配轮里做违背「不破坏现有布局」。
**避免**：新项目第一天就写全局重置；接手老项目遇「明明 max-width:100% 还超宽」先查 box-sizing。

### 21. antd v6 Card 卡头折行：两个坑 + 一个结构手法

- 语义 API 没有钩子：`styles.header` 落在 `.ant-card-head`，而 flex 行是其内层 `.ant-card-head-wrapper`，**没有对应的 styles 键**——只能「组件根类 + `:global(.ant-card-head-wrapper)`」一条规则（确认过 antd 未声明 `flex-wrap`，单条声明即可生效）；
- 只放开 wrapper 不够：`.ant-card-head-title` 自带 `white-space:nowrap + ellipsis`，折行后**标题在格内被省略号安静截断**——量测型门禁抓不到（没有溢出），是 375px 截图走查人工抓到的。必须一并放开 `-head-title` 的 nowrap；
- 标题内部结构：原来的 `[图标+文字+Tag]` 是一个原子 inline-flex span，挤压时中文被**逐字拆断**（「本学期/积分排/行」）。改成「文字包一层 nowrap 原子 span，Tag 作为可折行的兄弟节点」，折行时整组落下，不拆字。

### 22. 门禁的种子数据没有「脏内容」就会假绿

论坛页第一版门禁一次就过——因为 stub 种子全是正常中文，长 URL/无空格串/代码块这些真实风险**在演示数据里根本不存在**。门禁要守的是风险不是演示：论坛步骤前先向 stub 插一条含长 URL + 代码块 + 无空格长串的样例帖，再打开详情一起量。
**推广**：任何「防溢出/防截断」类断言，先问「最坏内容长什么样」，然后让测试数据长成那样。

### 23. 环境会在会话中途坏掉：多处症状可能同根因，分层探测 10 秒定位

E 盘在会话中途断连，同时表现为「所有 Read 报 File not found」+「Bash 报 spawn bash.exe ENOENT」——后者极具误导性（Node 的 spawn 在 **cwd 无效**时报 ENOENT 且错误文案指向可执行文件路径，会让人去查 Git 安装）。分层探测（`C:\Users\...` 正常 → `E:\` 全无）即定位：盘没了，等用户恢复，不瞎修。
**断盘后遗症会延迟出现**：commit-graph 链文件损坏 → 之后每条 git 命令都警告；`renaming pack failed: File exists` 是内容寻址同名包已存在，无害。**派生元数据（commit-graph、pack idx）删掉可重建**（`rm -rf .git/objects/info/commit-graph*` + `git commit-graph write --reachable`），对象库本体用 `git fsck` 确认。

### 24. 共享测试 helper 藏着 viewport 假设；偶发失败先单跑定性

`loginAs` 最后断言「侧边栏菜单可见」——桌面恒真，375px 下菜单在收起的 Drawer 里根本不在 DOM，门禁第一跑就挂在这。修法是给 helper 加可选参数 `{ mobile?: boolean }` 跳过桌面断言（向后兼容，老调用零影响），**不是**复制一个 mobile 版函数。另外全量 E2E 偶发挂一个用例时（本轮 phase3 资料编辑），先单跑该 spec 复现：单跑全过 = 环境抖动，与改动无交集，如实记录即可，不要 revert 也不要盲目重跑到绿。

## 给下一次接手的注意事项

1. **改任何页面后跑 `npx playwright test tests/e2e/mobile-overflow.spec.ts`**（约 12 秒）：375px 有溢出会直接点名页面和元凶元素；门禁报告自动落在 `docs/mobile-overflow-report.md`。
2. **给滚动容器内的页面加内容前**，记住判定口径：页面级（document/contentArea/弹窗遮罩）不许横滚；**有意横滚**（表格 scroll.x、看板、热力图）是既定形态，别在它们外层再包别的滚动器。
3. **写长文本容器**（Markdown/公告/说明）时默认带 `overflow-wrap:anywhere`；代码块和表格用 `overflow-x:auto` 内滚，不要断词。
4. **自定义 CSS 里写死宽度**时，先确认该元素有没有 border-box（本项目无全局重置），或者干脆用 `min(Npx,100%)` + `box-sizing:border-box` 成对写。
5. **修卡头/卡尾这种 antd 内部布局**，改完务必 375px 截图看一眼——省略号截断不产生溢出，门禁量不到，只有肉眼能验收。
6. **测试新增视口相关断言**时检查共享 helper 的桌面假设（`loginAs` 已有 `mobile` 选项先例）。
