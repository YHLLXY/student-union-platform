## 二、架构侧改动明细

### 1. Vendor 分包（rolldown codeSplitting）

- 用 sourcemap 字节审计定位 v3.6 遗留问题：`SkeletonBlocks` 命名的 chunk 实为 801KB 的 react-dom+antd+supabase 大杂烩，位于首屏关键路径
- `output.codeSplitting.groups` 六组分包（react-core/supabase/antd/motion/markdown/vendor），antd 组 `entriesAware: true` 让页面专属组件（Table/Tree/DatePicker）按需裂解
- 成果：入口应用代码 448KB → **65KB**（纯业务代码）；vendor 命名语义化、哈希稳定可缓存；最大 chunk 801KB → 386KB 语义清晰的核心共享块

### 2. 数据库类型（src/types/database.ts）

- 手写 14 张表 Row/Insert/Update + 字面量外键 Relationships，JSONB 列收敛业务类型
- `createClient<Database>` 后全链路类型检查，服务层清除全部 `as unknown as` / `Record<string, unknown>` 强转
- 摸清 supabase-js 嵌套推断规则：**双外键表必须 `别名:目标表!列名()` 提示**（探针实证，FK 名提示反而不行）
- 补录线上库超前于迁移脚本的列（invite_codes.created_by）

### 3. 服务层 + 数据层

- `lib/sb.ts`：unwrap / unwrapMaybe / unwrapCount，读函数「失败即抛 SbError」，终结静默空列表
- `lib/queryClient.ts`：staleTime 30s / retry 1 / 关焦点重取（刻意贴近旧行为缩小回归面）
- 10 个模块读路径全部迁移 useQuery；Realtime → invalidateQueries；看板拖拽、通知已读改 setQueryData 乐观更新
- 分层约定成文：路由级读数据必走 RQ；弹窗数据可命令式但必须 .catch；聚合搜索允许单源降级

### 4. 其他

- 路径别名 `@/`（tsconfig paths + vite alias，346 处）
- App.tsx 挂 onAuthStateChange，SIGNED_OUT 清用户态 + queryClient.clear()，修会话过期僵尸页
- **顺手修真 bug**：fetchUserStats 在 head 计数查询上取 data.length 恒为 0（个人页统计一直显示 0）

## 五、给下一次接手的注意事项

1. **改表结构必须同步 `src/types/database.ts`**（事实来源 supabase-migration.sql，同时留意线上库与脚本的差异列）
2. **新写 service 读函数一律 `unwrap` 抛错**，禁止返回 [] 伪装成功；写函数保持布尔/null 约定
3. **新页面读数据一律 useQuery**；Realtime 订阅回调里 invalidate，不要绕过缓存直 set state
4. tasks/invite_codes/platform_guides 是双外键表，嵌套 select 必须 `别名:users!列名()` 语法
5. emoji 退出 UI 的规则已成文（research/07 第五节）：数据层纯文本，图标展示层渲染
6. motion 动效依旧必须走 `src/components/motion` 封装层（v3.6 铁律延续）
7. 角色 chunk 已按使用面裂解，新增页面如果引入未用过的重型 antd 组件会自动进独立子块，无需改配置
8. 工作区历史过程文档的删除已作为独立 chore commit 提交（此前一直悬在工作区），如需恢复 `git revert` 即可
